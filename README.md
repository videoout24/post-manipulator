# Post Manipulator

[English](README.en.md) · **Русский**

Post Manipulator — утилитарный MVP для сборки, публикации и управления связанными постами. Он рассчитан на возможности Telegram и не требует развёрнутого бэкенда или платного хостинга.

## Что умеет

- собирать и редактировать Rich Message;
- сохранять наборы блоков как пользовательские шаблоны;
- быстро менять порядок и вложенность блоков в сообщении;
- работать с проектами, черновиками, публикациями и медиа;
- планировать публикацию обычных черновиков и проектов (внутренней абстракции
  связанных постов), а также редактировать их после публикации;
- получать медиа от привязанного владельца через бота;
- показывать live-preview в отдельном приватном канале;
- удалять доступные Bot API сервисные сообщения из личного чата владельца и preview-канала;
- создавать и восстанавливать резервные копии IndexedDB через Telegram;
- импортировать таблицы `.csv` и `.md` в нативные Rich Message-блоки;
- импортировать LaTeX-шаблоны формул из подготовленных `.json`-файлов;
- использовать любую нейросеть для генерации поста через протокол
  `handleCopyPaste`: экспортировать структурированный AI JSON, передавать его
  модели и применять ответ через copy/paste или локальный `.json`-файл.

## Импорт проектов и тестовый набор

В разделе «Проекты» кнопка «Импорт» добавляет проект из `.json` в текущую
IndexedDB. Можно выбрать сразу несколько файлов: один файл обычно содержит один
проект, а bundle с форматом `rich-current-projects` — несколько. Импорт не
очищает базу; совпавший ID превращается в новый ID и создаёт копию проекта.
Состояние публикации, отложка и Telegram `chat_id` / `message_id` всегда
сбрасываются, чтобы импортированный проект не мог управлять сообщениями исходной
среды.

Готовый нагрузочный набор лежит в [`data/test-projects`](data/test-projects):
20 отдельных проектов по 10 постов, минимум 5 контентных блоков в каждом посте,
карта в стартовом посте и 10 изображений из [`assets/test-projects`](assets/test-projects).
Все проекты сразу можно загрузить файлом
[`data/test-projects-bundle.json`](data/test-projects-bundle.json). Набор
детерминированно пересобирается командой:

```bash
node scripts/generate-test-projects.mjs
```

## Что намеренно не делалось

Прямой AI API сознательно не интегрирован: инструмент в первую очередь рассчитан на работу с авторским текстом. При желании редактор можно дополнить коннектором к API конкретного AI-провайдера, но это фактически убьёт саму задумку — приятная работа с выражением своих мыслей вместо тотальной генерации.

## AI JSON: запрос без обязательного AI API

У каждого блока на Canvas есть сворачиваемое поле «AI-запрос» сразу под строкой
названия и кнопок. Для запроса можно разрешить изменение всего блока или только
одного его поля. Инструкция сохраняется в служебном объекте `node.ai`, остаётся в
AST после ответа и не попадает в Telegram Rich Message при публикации.

Кнопка `AI JSON` формирует переносимый пакет `rich-current-ai-draft`. В нём есть:

- ID и версия исходного черновика или поста проекта;
- полный структурированный AST либо окружение целевого блока;
- точная область разрешённого изменения (`message`, `block` или `field`);
- инструкции блоков и контракт, требующий вернуть полный JSON без изменения структуры;
- `task.blockSchemas` — ожидаемую форму `props` и `children`, полученную из
  реестра блоков и свойств. Схема каждого встреченного типа добавляется один раз:
  например, три списка используют одну `task.blockSchemas.list`, а две таблицы —
  одну `task.blockSchemas.table`;
- `task.richTextSchema` — единое описание допустимых представлений Rich Text;
- `task.formatSets` — уникальные наборы Rich Text-форматов. Текстовые свойства
  используют короткий `formatSet: "f1"`, поэтому одинаковые представления и
  списки форматов не повторяются в схемах заголовков, таблиц и подписей.

Пакет содержит только внутренние идентификаторы приложения (`request.id`, ID
черновика/проекта/поста и блоков AST). `chat_id`, `message_id`, ID канала и ID
редактируемой Telegram-публикации в него не включаются.

Кнопка `AI JSON блока` всегда формирует изолированный пакет только с целевым
блоком и его вложенным содержимым и использует только промпт этого блока. На
каждой карточке обычного черновика и на карточке активного поста всегда показана
секция `Промпт всего черновика` или `Промпт всего поста`, независимо от наличия
AI-запросов в блоках. Поле занимает всю ширину карточки и использует общий
механизм изменения высоты полей редактора: по умолчанию подстраивается под число
строк подсказки, затем растёт вместе с содержимым и сохраняет выбранную вручную
высоту на время сессии. Компактная кнопка `{}` для открытия
документного AI JSON находится в общем блоке кнопок карточки. Этот отдельный
промпт получает полный AST и может описывать связи между блоками, например
заполнение списка и следующих за ним параграфов. При пустом документном промпте
действуют только локальные запросы блоков. У выбранного обычного черновика кнопка
`Закрыть` сохраняет его и очищает Canvas.

Пакет можно скопировать или скачать, а затем передать любой нейросети. Ответ
вставляется вручную в поле AI JSON обычной системной командой вставки либо
выбирается как локальный `.json`-файл. Кнопка `Применить ответ` полностью проверяет
пакет; при ошибке открывается диалог с причиной, а исходный текст остаётся в поле
для исправления. Из-за ограничений CORS приложение не отправляет JSON через бота,
не читает ответы из чата и не предоставляет отдельную кнопку чтения clipboard.
Любые JSON-документы, полученные ботом, игнорируются и в Галерею не добавляются.
Кнопка `Открыть бота` остаётся отдельной навигационной командой. Подключение AI
API позже сможет использовать тот же пакет и импортёр без изменения формата
черновиков.

Изолированный ответ применяется обратно только к разрешённому блоку или полю.
Если версия источника изменилась после экспорта, приложение показывает диалог
конфликта и ничего не меняет автоматически. В нём можно применить ответ к
текущей версии, создать отдельный черновик или отменить импорт без изменений.
Ответ на запрос ко всему сообщению по-прежнему импортируется отдельным черновиком.

Для блоков Animation, Audio, Document, Photo, Video и Voice note AI может вернуть
прямой публичный HTTPS URL: Telegram умеет загрузить такой файл при отправке.
В блоках с поддержкой Gallery внешний URL и внутренний ресурс взаимоисключаются:
ввод URL очищает `galleryId` и Telegram `file_id`, а выбор ресурса Gallery очищает
URL. Ссылка должна вести непосредственно на файл с корректным MIME и может
оказаться временной, поэтому для долговечных публикаций предпочтительнее Gallery.
По общим правилам Bot API загрузка по URL ограничена 5 МБ для фото и 20 МБ для
остальных файлов; для документов гарантированы PDF и ZIP, а для голосовых — OGG
до 1 МБ. Подробности приведены в [Telegram Bot API](https://core.telegram.org/bots/api#sending-files).

## Блок Map

Блок Map принимает полную ссылку Google Maps, Telegram/`geo:`, Яндекс Карт, Apple Maps
или 2GIS, если ссылка содержит координаты. Редактор сам определяет провайдера,
извлекает широту, долготу и доступный масштаб. Короткие ссылки намеренно не
поддерживаются: статическое приложение не может прочитать их междоменные
редиректы, поэтому такую ссылку нужно сначала открыть и скопировать полный адрес.
Масштаб ограничен значениями `1–20`. Размер в пикселях не редактируется: доступны
только кнопки «Ландшафт 2:1» и «Портрет 1:2», которые преобразуются в допустимые
для [Telegram InputRichBlockMap](https://core.telegram.org/bots/api#inputrichblockmap)
`width` и `height`. Поле точности не используется.

## Внутренний сборщик блоков

У каждого пользовательского блока перед заголовком в верхней строке Canvas есть
тоггл-ромб. При включении он получает неоновую рамку, а в IndexedDB сохраняется внутренняя ссылка на исходный
черновик или пост проекта и ID блока. Так можно собирать блоки, переходя между
разными постами и черновиками.

Рядом с кнопкой «Черновики» команда «Вставить буфер» добавляет в конец текущего
Canvas независимые копии всех собранных блоков. Копии получают новые внутренние
ID и сохраняют вложенное содержимое; после вставки буфер не очищается. «Очистить
буфер» удаляет все ссылки и выключает активные тогглы. Пока буфер непуст,
обе команды подсвечены неоновой рамкой. Управляемые структурой
проекта блоки «Карта постов» и «Назад к карте» не добавляются в сборщик.

Ссылки валидируются при каждом изменении дерева, черновика, поста или проекта.
Удаление исходного блока, его поста, черновика или проекта автоматически удаляет
устаревшую ссылку. Полная проверка дополнительно выполняется перед вставкой.

Справа от команды «Очистить буфер» расположен селектор скорости автоматического
позиционирования активного блока: `0` отключает подскроллинг, `1` — медленный
режим, `2` — скорость примерно вдвое ниже прежней и используется по умолчанию,
`3` — прежняя скорость. Настройка сохраняется локально для всего редактора.

## Почему нет бэкенда

Для MVP бэкенд не нужен: приложение предназначено для личной работы владельца с собственным ботом, а Telegram уже предоставляет необходимые возможности — Mini App, CloudStorage, Bot API и личный чат для резервных копий. Это даёт бесплатное развёртывание на статическом хостинге и не создаёт отдельную базу данных с token на сервере.

Из этого следуют ограничения:

- long polling работает, только пока Post Manipulator открыт и запущен в Telegram Desktop;
- у бота не должен быть активный webhook: Telegram не позволяет одновременно использовать webhook и `getUpdates`;
- приложение не заменяет серверную автоматизацию, фоновые задачи или совместную работу нескольких операторов;
- для работы с token используйте только доверенную опубликованную копию приложения.

В дальнейшем бэкенд планируется реализовать не как обязательную централизованную часть приложения, а как независимый сервис, снимающий ограничения client-only архитектуры. При его разработке предполагается сохранить минимальные расходы на развёртывание и эксплуатацию.

## Ограничения отложенных публикаций

Посты проекта добавляются в отложку по порядку: все предыдущие должны быть
опубликованы или запланированы, а время следующего — не раньше их времени.
Одинаковое время допустимо: отправка выполняется последовательно, начиная с
карты проекта. Немедленная публикация по-прежнему требует публикации всех
предыдущих постов. Отложку отменяют с конца; перенос предшественника на более
позднее время требует сначала перенести последующие посты.

Расписание хранится в локальной IndexedDB. Пока Mini App открыта, публикация запускается таймером. Закрытое статическое приложение не выполняет фоновые задачи: если назначенное время прошло, запись будет отправлена сразу после следующего успешного запуска приложения; при временной ошибке сервис повторяет попытку раз в минуту, пока приложение остаётся открытым. Поэтому отложка не является серверным планировщиком и зависит от сохранности локальной базы, действующего Bot API token и доступности выбранного чата.

## Особенности реализации

Post Manipulator — статическое client-only приложение: его можно разместить на GitHub Pages или любом HTTPS-хостинге без сервера приложений.

| Часть | Где работает и за что отвечает |
| --- | --- |
| Интерфейс и редактор | Полностью в браузере Telegram Desktop. Сайт состоит из статических HTML, CSS и JavaScript-файлов. |
| Локальные данные | Для каждого Publisher Bot ID создаётся отдельная IndexedDB `post-manipulator-bot-<botId>`. Там лежат проекты, черновики, настройки, preview-состояние и несекретные привязки. |
| Bot API token | В IndexedDB не сохраняется. После первого запуска token шифруется паролем и помещается в Telegram CloudStorage; расшифрованный token существует только в памяти активного запуска. |
| Telegram-интеграция | Браузер обращается к Telegram Bot API напрямую. `TelegramRuntime` получает updates через long polling, а остальные модули публикуют, редактируют и удаляют сообщения. |
| Привязка владельца | Подписанный `initData` сразу привязывает пользователя Mini App к локальной базе. Нажатие Start в личном чате нужно только для того, чтобы Bot API получил право отправлять ему сообщения и принимать media. |
| Резервные копии | Резервная копия текущего локального storage отправляется закреплённым документом в личный чат владельца. При каждом запуске приложение проверяет самую новую закреплённую запись по дате отправки и предлагает восстановление, если копия новее локальной базы. |

### Модель угроз и остаточные риски

Схема защищает Bot API token при хранении, но не превращает Telegram WebView в доверенную аппаратную среду и не шифрует рабочие данные. Защищённый запуск проверяет Ed25519-подпись Telegram, Bot ID и возраст `initData` на момент открытия security-сессии — не более 30 секунд. После принятия запуска время на ввод пароля не ограничено этим окном. Token хранится в CloudStorage как AES-256-GCM-контейнер с отдельными salt и IV; ключ выводится из пароля через PBKDF2-SHA-256 с 600 000 итераций. Telegram изолирует CloudStorage по паре «бот + пользователь», поэтому фиксированный ключ `rmb_token_v2`, Bot ID и User ID не являются секретами.

Модель предполагает доверенные ОС и Telegram Desktop, точный HTTPS-origin из BotFather и неизменённый JavaScript приложения. Если одно из этих условий нарушено, криптографический контейнер сам по себе не спасает.

Хранение зашифрованного token в CloudStorage служит только удобству повторного входа и не является обязательным условием работы с Bot API. Практически session-only режим мог бы запрашивать token при каждом запуске и вообще не создавать облачный контейнер. Это уменьшило бы количество постоянных копий token и устранило бы риск офлайн-подбора пароля к контейнеру, но не решило бы основную проблему активной сессии: после ввода token всё равно находится в памяти WebView и используется в URL запросов Bot API. Поэтому отказ от CloudStorage меняет удобство и защиту данных в покое, но не защищает от скомпрометированного JavaScript, WebView или устройства во время работы.

Более строгий режим эксплуатации возможен и без отключения CloudStorage: после завершения работы владелец может вручную перевыпустить token через `@BotFather`. Сохранённый контейнер тогда содержит уже недействительный token и не даёт доступа к боту даже после успешного подбора пароля. При следующем запуске приложение получит `401`, предложит ввести новый token того же бота, проверит Bot ID и подписанный `initData`, затем заменит контейнер. Существующая IndexedDB этого бота на устройстве сохранится; после очистки browser storage её, как обычно, потребуется восстановить из backup. Такой подход ограничивает срок полезности похищенного token, но не отменяет уже выполненные с ним действия и не удаляет ранее загруженные байты миниатюр из HTTP-кэша WebView.

| Риск | Что реально может произойти | Что делать владельцу |
| --- | --- | --- |
| Подмена сайта, XSS или стороннего JavaScript | Любой скрипт внутри страницы, включая подключаемый `telegram-web-app.js`, имеет доступ к форме пароля, расшифрованному token, CloudStorage и IndexedDB. Компрометация хостинга, аккаунта GitHub, WebView или расширения обходит шифрование. | Использовать только точный доверенный URL, защищать аккаунт и ветку публикации, проверять изменения перед deploy и не вводить token в чужих копиях приложения. |
| Утечка token во время активной сессии | После входа token находится строкой в памяти и входит в URL Bot API вида `https://api.telegram.org/bot<token>/...`. URL миниатюр также попадает в DOM и browser HTTP cache. Отладчик, вредоносный процесс или внедрённый скрипт могут его прочитать; очистка ссылок в JavaScript не гарантирует физическое стирание памяти. | Использовать отдельного бота с минимальными правами. При подозрении на утечку немедленно перевыпустить token через `@BotFather`: владелец token получает полный контроль над ботом и всеми доступными ему чатами. |
| Офлайн-подбор пароля | Полученный из CloudStorage контейнер позволяет проверять догадки по тегу AES-GCM без серверного rate limit. PBKDF2 замедляет перебор, но не компенсирует короткий или словарный пароль; требование «8 символов, буква и цифра» не гарантирует достаточную энтропию. | Использовать уникальную длинную парольную фразу или пароль из менеджера паролей, не совпадающий с паролем Telegram. |
| Открытые локальные данные и backup | IndexedDB и экспортируемый JSON не шифруются. Backup не содержит Bot API token, но содержит проекты, черновики, настройки, Telegram chat/file IDs и привязки. Их может прочитать тот, кто получил доступ к профилю WebView, Telegram-аккаунту, личному чату или скачанному файлу. | Защищать устройство локальным паролем, включить код-пароль и двухэтапную аутентификацию Telegram, удалять лишние скачанные копии и не хранить в редакторе данные, которым нужно сквозное шифрование. |
| Подмена резервной копии | JSON проверяется на совместимость формата, но не подписан, не имеет MAC и при импорте полностью заменяет локальную базу. Специально подготовленный файл может подменить контент, настройки и Telegram-привязки либо попытаться использовать ошибку отображения импортированных данных. | Восстанавливать только собственные копии, созданные этим ботом; не принимать backup-файлы от третьих лиц. |
| Компрометация Telegram-аккаунта или устройства | Другой Telegram-аккаунт не имеет доступа к backup. Риск возникает, только если злоумышленник получил авторизованную сессию именно аккаунта владельца: личный чат с ботом является обычным облачным чатом Telegram, поэтому его сообщения и закреплённый JSON синхронизируются между устройствами этого аккаунта. Содержимое CloudStorage не показывается в интерфейсе Telegram: зашифрованный контейнер может запросить JavaScript Mini App в области этой же пары «бот + пользователь», но без пароля контейнер не раскрывает token. Если на скомпрометированном устройстве Mini App уже разблокирована, token и локальная база доступны в активном WebView. | Регулярно проверять активные сессии Telegram, включить двухэтапную аутентификацию и локальный код-пароль, завершать неизвестные сессии. |
| Ограниченность client-only проверки | Подпись `initData` подтверждает происхождение и целостность данных Telegram, но проверяется в том же WebView: это не device attestation, серверная сессия, аудит или удалённая блокировка. Захваченный корректный `initData` позволяет открыть security-сессию только в пределах 30-секундного окна, хотя без пароля он не расшифрует token. Уже принятая сессия может оставаться открытой дольше. | Не считать проверку Telegram защитой от владельца скомпрометированного устройства. Для многопользовательского или серверного сценария переносить авторизацию и Bot API token на backend. |
| Потеря доступности | IndexedDB может быть очищена клиентом, CloudStorage или Bot API могут быть временно недоступны, а закреплённый backup — удалён или заменён. Шифрование не защищает от потери данных. | Создавать копии после важных изменений, периодически сохранять их отдельно и проверять восстановление. |

Telegram описывает область CloudStorage и проверку подписанного `initData` в документации [Mini Apps](https://core.telegram.org/bots/webapps#cloudstorage) и [third-party validation](https://core.telegram.org/bots/webapps#validating-data-for-third-party-use). Согласно документации Telegram, любой получивший Bot API token получает [полный контроль над ботом](https://core.telegram.org/bots#how-do-i-create-a-bot).

### Проверка и восстановление резервных копий

Telegram допускает несколько закреплённых сообщений. Метод Bot API `getChat` возвращает самое новое из них по дате отправки, поэтому именно оно используется как кандидат на автоматическое предложение восстановления. Если последним было закреплено не backup-сообщение, более старые закрепы Bot API перечислить не позволяет — нужный JSON-файл всё равно можно восстановить вручную в разделе «Настройки → Резервные копии». См. описание [`ChatFullInfo.pinned_message`](https://core.telegram.org/bots/api/#chatfullinfo).

Свежесть определяется сравнением серверной даты отправки закреплённого документа с последним изменением содержательных записей локальной IndexedDB. Проверка выполняется после защищённого входа, но до запуска редактора — и для пустой, и для уже заполненной базы. Приложение никогда не перезаписывает данные автоматически: оно показывает предложение, пользователь скачивает выбранный JSON из Telegram и явно подтверждает восстановление. Импорт полностью заменяет локальную базу, запоминает применённую копию и продолжает запуск приложения в той же странице без `reload`; поэтому сбрасывающий IndexedDB Linux WebView больше не замыкает восстановление в цикл.

Bot API позволяет боту получить через `getFile` путь к файлу размером до 20 МБ, но статическая Mini App не является серверным Bot API-клиентом. Telegram file endpoint не разрешает JavaScript прочитать ответ через CORS, а `Telegram.WebApp.downloadFile()` только показывает системный диалог скачивания и не возвращает приложению байты файла. Поэтому без отдельного backend пользователь один раз скачивает JSON и выбирает его в форме восстановления. См. [`getFile`](https://core.telegram.org/bots/api/#getfile) и [`downloadFile`](https://core.telegram.org/bots/webapps#initializing-mini-apps).

### Подтверждённая проблема Telegram Desktop для Linux

В протестированном Linux-клиенте Telegram Desktop хранилище WebView сбрасывается между перезапусками: IndexedDB корректно создаётся и работает в активной сессии, но после повторного открытия Mini App локальная база отсутствует. На Windows тот же build подтверждённо сохраняет IndexedDB между перезапусками. Telegram Desktop для macOS пока не тестировался. Это ограничение Linux WebView клиента, и приложение не может предотвратить удаление его локального browser storage.

Зашифрованный Bot API token при этом остаётся в Telegram CloudStorage, но проекты, черновики, настройки и остальные локальные данные необходимо восстановить из последней резервной копии. До исправления Linux-клиента:

- создавайте резервную копию после значимых изменений;
- храните актуальную закреплённую копию в личном чате с ботом;
- после ввода пароля восстановите предложенную последнюю копию: импорт выполняется до запуска приложения и не вызывает повторную перезагрузку; при непустой базе приложение также предложит закреплённую копию, если она свежее;
- для работы с подтверждённым сохранением локальной базы используйте проверенный Windows Telegram Desktop.

Схожий сброс WebView storage в Linux Telegram Desktop зарегистрирован в [telegramdesktop/tdesktop#31051](https://github.com/telegramdesktop/tdesktop/issues/31051).

## Быстрый старт

### 1. Подготовьте бота и выберите адрес Mini App

Технически Post Manipulator не привязан к одному боту или одному хостингу. Можно использовать готовую страницу проекта либо развернуть ту же кодовую базу у себя — дальнейшая настройка и сценарий первого запуска одинаковые.

Создайте бота в `@BotFather`. После выбора адреса настройте **Main Mini App** и **Menu Button**. Main Mini App даёт кнопку запуска в профиле бота, а кнопка меню позволяет открывать приложение прямо из чата.

Дальше два варианта:

**Вариант A — использовать общую страницу проекта.**

После публикации GitHub Pages укажите в BotFather этот адрес Mini App:

```text
https://videoout24.github.io/post-manipulator/?build=1.11.0
```

Ваш bot token останется зашифрованным в Telegram CloudStorage, а данные приложения — в локальной IndexedDB выбранного бота. Страница не требует заранее заданного Bot ID.

**Вариант B — развернуть свою копию.**

Склонируйте или форкните репозиторий и опубликуйте его на GitHub Pages, Cloudflare Pages, Vercel, Netlify или любом другом HTTPS-хостинге. Для GitHub Pages:

1. Создайте на GitHub публичный репозиторий, например `post-manipulator`.
2. Свяжите локальную папку с репозиторием и отправьте код:

   ```bash
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/post-manipulator.git
   git push -u origin main
   ```

3. В репозитории откройте **Settings → Pages**.
4. Выберите **Deploy from a branch**, ветку `main` и папку `/(root)`.
5. Адрес будет иметь вид:

   ```text
   https://<ваш-логин>.github.io/post-manipulator/
   ```

Разница между вариантами только в том, кто управляет обновлениями страницы. Поскольку на странице вводится Bot API token, используйте только хостинг и опубликованный код, которым доверяете.

### Настройка кнопок в BotFather

После того как у вас появился HTTPS-адрес Mini App:

1. В `@BotFather` выполните `/mybots` и выберите своего бота.
2. В настройках **Mini App** задайте этот URL как **Main Mini App**.
3. В настройках **Menu Button** или через команду `/setmenubutton` задайте:
   - текст кнопки: `Post Manipulator`;
   - URL: тот же HTTPS-адрес Mini App.

Обе настройки используют один и тот же URL. После этого приложение можно открыть и из профиля бота, и из меню чата.

### 2. Первый вход и привязка владельца

1. Откройте чат с ботом в Telegram Desktop и нажмите **Start**.
2. Откройте Post Manipulator через кнопку Mini App.
3. Придумайте и подтвердите пароль.
4. Введите Bot API token этого бота.
5. Приложение вызывает `getMe`, получает Bot ID, проверяет подписанный Telegram `initData` и только затем сохраняет привязку пользователя и зашифрованный token.

Telegram автоматически изолирует CloudStorage по паре «бот + пользователь», поэтому encrypted token хранится под единым ключом `rmb_token_v2`. Значение содержит только версию формата, PBKDF2 salt/iterations и AES-GCM IV/ciphertext — открытых Bot ID или User ID в нём нет. После расшифровки приложение получает Bot ID через `getMe`, проверяет подпись `initData` и лишь затем открывает IndexedDB `post-manipulator-bot-<botId>`. Сам пароль и token в IndexedDB не сохраняются.

### 3. Привяжите канал предпросмотра

Только после успешного первого входа создайте **приватный канал** (не группу) и добавьте в него бота администратором. Выдайте ему права публиковать, редактировать и удалять сообщения.

Админские права задаются при добавлении бота в конкретный канал, а не в BotFather. Для автопривязки оставьте в канале только текущего владельца и бота.

Канал привяжется автоматически, если одновременно выполнены условия:

- канал приватный;
- бот является администратором;
- текущий владелец состоит в канале;
- участников ровно двое: владелец и бот.

После привязки приложение создаст и закрепит служебное сообщение для live-preview. Если условия не выполнены, используйте ручную привязку с кодом в настройках.

## Обновление сайта

После изменений:

```bash
git add <файлы>
git commit -m "Описание изменения"
git push
```

GitHub Pages обновит сайт автоматически.

GitHub Pages и Telegram Desktop могут сохранить прежний `index.html`, поэтому после каждого релиза увеличивайте параметр `build` в URL Mini App в BotFather, например `?build=1.11.0`. Параметр должен быть одинаковым для Main Mini App и Menu Button; `#fragment` для этого не подходит. Полностью отключить такой кэш на GitHub Pages нельзя — для управляемого `Cache-Control: no-store` нужен другой хостинг, например Cloudflare Pages.

## Локальная проверка

Smoke-тесты запускаются Node.js:

```bash
for test_file in tests/*_smoke.mjs; do node "$test_file"; done
```

Браузерная проверка темы: запустите `python3 -m http.server 8000` и откройте
`http://localhost:8000/tests/theme_browser_smoke.html` в обычном браузере.
Результат доступен в консоли как `theme_browser_smoke: OK` и в
`window.themeSmokeResult`. Это изолированный тест интерфейса без подключения бота.
Для визуальной проверки используйте `showThemeFixture("light", "settings")`
или режимы `dark`, страницы `editor` и `gate`.

Полный сценарий авторизации и Telegram CloudStorage можно проверить только в Telegram Desktop. Не публикуйте Bot API token в коде, коммитах или настройках GitHub Pages.
